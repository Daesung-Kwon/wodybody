## 4. 측정 지표 진행 현황

Sprint 3 Phase C 의 분석 이벤트(`lib/analytics.ts` + 6종) 부착으로 *측정 인프라*는 갖춰졌다.
운영자가 Plausible 대시보드에 도메인을 설정(`VITE_ANALYTICS_DOMAIN`)하면 아래 지표를
이벤트 기반으로 산출할 수 있다.

| 지표 | 측정 가능 여부 | 근거 이벤트 |
|------|----------------|-------------|
| CR1 챌린지 완주율 | ✅ 가능 | `submission_submitted`(type=start/end) |
| CR2 주간 기록 입력률 | ✅ 가능 | `weekly_log_created`(week_no) |
| CR3 AI 조언 재방문률 | ◐ 부분 | `ai_advice_requested` — 재방문은 별도 세션 분석 필요 |
| CR4 코치 모달 진입률 | ✅ 가능 | `coach_modal_opened` / `ai_advice_requested` 비 |
| CR5 코치 멀티턴 평균 | ✅ 가능 | `coach_message_sent`(turn_index) |
| GR1 챌린지 재생성률 | ◐ G3 구현 후 | `challenge_created` — 재생성 플래그는 G3 에서 추가 |
| GR2 외부 유입 비중 | ◐ G2 구현 후 | 공유 링크 `?ref=` 파라미터 측정 필요 |

> 다음 단계: 운영자가 Plausible 도메인을 설정하고 6종 이벤트의 첫 도착을 확인한 뒤,
> 위 지표를 대시보드 목표(funnel/속성)로 구성한다.

## 5. 권장 진입 순서

1. **G3 (재시작 1-click)** — 가장 작고, GR1 측정과 직결. 리텐션 빠른 승.
2. **G2 (카카오 공유)** — GR2 측정 + 신규 유입. G1 과 공유 자산 공통.
3. 이후 **S1 → S2** 묶음(인증 전환) 또는 **P1**(팀 모드) 중 제품 방향에 따라 선택.

대안: 신규 기능 대신 **운영 안정화 기간** — gunicorn 재전환 검증, 분석 이벤트 첫 데이터
수집·해석, 사용자 피드백 수렴에 한 분기를 쓰는 것도 합리적이다.
