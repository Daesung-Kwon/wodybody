# G3. 체지방 입력 — 민감정보 별도 동의 (제23조)

상태: **코드 초안 (2026-10-28). 배포하지 않음.** PR #30 문서 초안(사진 포함, "미구현")은 main에 머지된 뒤 이 파일로 대체한다. 수집은 숫자만(PR #31)이다. 마이그레이션은 적용하지 않는다.

결정: 체지방 입력은 선택이고, 비공개이며, 동의한 뒤에만 저장한다. 사진은 받지 않는다.

개인정보 보호법 제23조는 민감정보를 원칙적으로 처리하지 못하게 하고, 정보주체 동의 등으로 예외를 둔다. 체지방률을 건강 관련 정보로 보고 별도 동의를 받는다. 민감정보 해당 여부는 법률 확인으로 확정한다. 인바디 인쇄 이미지는 수집 항목에서 빠졌다.

가입 동의(G2)·국외 이전 동의(G4)와 칸을 합치지 않는다.

## 화면

`BodyFatConsentFields`: 제목 "체지방 정보 수집 동의 (선택)", 짧은 본문, 체크 기본 꺼짐. 가입 마법사 안에 두지 않는다.

체크 문구: "위 내용으로 체지방 정보를 수집·저장하는 데 동의합니다."

들어가는 곳:

- 시작·종료 인증 `SubmitModal` — 숫자가 있는데 체크가 없으면 제출하지 않는다. 빈 값은 RPC가 NULL을 거절하므로 인증 행을 만들지 않는다 (취소와 같음). `imagePath` 는 null
- 주간 기록 `WeeklyLogForm` — 체지방이 없으면 다른 항목만 저장 (`body_fat_rate` null). 숫자가 있으면 동의 없으면 전체 저장을 막는다
- 목표 체지방 `ParticipantBasicInfoDialog` — 같은 게이트. 동의 기록이 없는 기기에서는 기존 목표를 보여 주지 않고, 빈 칸으로 저장해도 기존 값을 지우지 않는다

## 동의 시각

컬럼이 없다. `localStorage` 키 `burnfat:body-fat-consent:<participantId>`.

값: `consentedAt`, `policyVersion` (`2026-10-28`), `purpose: body_fat`, `participantId`. 체지방 숫자는 넣지 않는다.

서버 RPC는 동의 행을 다시 보지 않는다. 그 검사는 소유자 승인 마이그레이션 뒤의 일이다.

## 비공개 (화면)

이 브라우저의 device secret 이 있는 행만 숫자를 보여 준다. 그 외는 "비공개". 순위 표·공유 문구도 같다. 참가자 목록은 체지방 순으로 정렬하지 않는다.

한계: `get_room_participants` 는 아직 숫자를 내려 준다. 응답 차단은 서버 마이그레이션이 필요하며 이 PR에서 적용하지 않는다.

## 검증

- 동의 없이 체지방을 넣으면 저장 API를 호출하지 않는다
- 동의 후 시작 인증은 `imagePath: null`
- 주간 기록은 체지방 없이 다른 필드를 저장할 수 있다
- 버킷에 새 인바디 객체는 동의 여부와 관계없이 생기지 않는다
