# G6. www Plausible 설치 계획

상태: **계획 초안. 스크립트를 넣거나 가입·결제하지 않음.** 비용은 승인 A2가 난 뒤에만 발생한다. 요금은 바뀌므로 승인 시점에 소유자가 [plausible.io](https://plausible.io) 요금표를 확인한다. 이 문서는 금액을 적지 않는다.

대상은 **www 프론트** (`frontend/`, www.wodybody.com)다. `burnfat/index.html` 에는 이미 `data-domain="burnfat.wodybody.com"` 스크립트가 있다. www 계획과 도메인을 섞지 않는다.

현재 www: `frontend/index.html` 에 Plausible 스크립트가 없고, `frontend/src` 에 `plausible` / `analytics` 호출이 없다. 가격 화면(₩4,900 / ₩9,900 / 연 ₩39,000)도 저장소에 없다. 가격 클릭 이벤트는 가짜 문 UI가 생긴 뒤에 연결한다. 결제는 만들지 않는다 (D4).

## 1. 스크립트 위치

`frontend/index.html` 의 `</head>` 직전.

```html
<script defer data-domain="www.wodybody.com" src="https://plausible.io/js/script.tagged-events.js"></script>
```

- `script.tagged-events.js` 는 페이지뷰를 자동으로 보내고, 커스텀 이벤트도 받는다.
- `data-domain` 이 `www.wodybody.com` 이므로 로컬과 Vercel 미리보기 호스트의 조회는 이 사이트로 집계되지 않는다.
- 설치는 A2로 사이트가 생긴 뒤, 소유자가 프로덕션에 반영한다 (A12). 이 PR은 HTML을 수정하지 않는다.

## 2. 환경 변수

| 이름 | 값 | 어디 |
| --- | --- | --- |
| `VITE_ANALYTICS_DOMAIN` | `www.wodybody.com` | Vercel Production 만 |

개발·미리보기는 비운다. `frontend/src/lib/analytics.ts` (신규, 이번 PR에서 만들지 않음)의 `track()` 은 이 값이 없으면 아무 것도 하지 않는다. BurnFat의 `burnfat/src/lib/analytics.ts` 와 같은 방식(PII 키 제거, 실패 무시)을 따른다.

페이지뷰 스크립트는 HTML에 고정하고, 커스텀 이벤트만 환경 변수로 끈다. 미리보기 호스트는 도메인이 달라 Plausible이 페이지뷰를 받지 않는다.

## 3. 커스텀 이벤트

이름은 소문자 밑줄. props에 이메일·닉네임·카카오 id를 넣지 않는다.

| 이벤트 | 언제 | props |
| --- | --- | --- |
| `landing_view` | www 랜딩이 마운트될 때 1회 | 없음. 자동 페이지뷰와 별도로 남겨 퍼널 시작을 고정 |
| `price_click` | 가짜 문 가격을 클릭 | `plan`: `4900` \| `9900` \| `yearly` (월 ₩4,900 / 월 ₩9,900 / 연 ₩39,000). 결제 호출 없음 |
| `signup` | 가입 완료가 서버에서 성공한 뒤 | 없음 |
| `wod_complete` | 오늘의 크로스핏식 WOD 완료 저장 성공 | `day_index` 정도만 (1–21). 기록 원문 금지 |
| `share` | 공유 시트가 열리거나 링크 복사가 성공 | `channel`: `copy` \| `native` |
| `crew_invite` | 크루 초대 링크를 만든 뒤 | 없음. 초대 대상 연락처 금지 |

호출 예:

```ts
track('price_click', { plan: '9900' });
```

가격 UI가 생기기 전에는 `price_click` 을 붙일 곳이 없다. 이벤트를 빈 버튼에 미리 달지 않는다.

## 4. 도착 확인

A2·배포 후에 소유자가 한다.

1. Plausible에 사이트 `www.wodybody.com` 이 있고, 커스텀 이벤트가 허용돼 있는지 본다.
2. 프로덕션(또는 `data-domain` 과 같은 호스트)에서 랜딩을 연 뒤 실시간(Live)에 페이지뷰와 `landing_view` 가 보이는지 확인한다.
3. 각 이벤트를 한 번씩 발생시키고 Live 또는 Goals에 이름이 나타나는지 확인한다. `price_click` 은 props `plan` 세 값이 각각 한 번씩.
4. `npm run dev` (localhost)에서는 커스텀 이벤트가 나가지 않는지, 네트워크 탭에 `plausible.io` 커스텀 POST가 없는지 확인한다.
5. 이벤트 페이로드에 `@` 또는 닉네임이 없는지 한 건만 본다.

가입·결제는 이 계획의 단계가 아니다.
